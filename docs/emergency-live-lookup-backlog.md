### 1.3 재생성 절차


**결정적입니다.** 같은 입력이면 출력이 바이트 단위로 동일합니다 (2026-11-18 검증: 재실행 후 `diff` 무변화). 따라서 재생성 후 `git status` 가 깨끗하면 정상입니다.

### 1.4 알려진 한계 — 이건 "버그"가 아니라 의도된 범위

| 한계 | 이유 / 대응 |
|---|---|
| **119안전센터·지구대·파출소 등 세부 관서 미포함** | 데이터 신선도 문제. 소방서·경찰서 단위까지만 자동 채우고 세부 관서는 담당자 확인 대상으로 남김 (행 `note` 에 "119안전센터 확인 필요" 문구 유지) |
| **`'일부'` 관할 37건이 목록에 남아 있음** | 의도적 선택. 안전 앱에서는 **실제 관서를 빠뜨리는 것보다 하나 더 나열하는 것이 안전**하므로, 부분 관할을 삭제하지 않고 전체 관할 뒤에 정렬 |
| **다중 기관 45행** | 한 구를 여러 경찰서가 나눠 맡는 경우가 실제로 존재(예: 서울 종로구 → 종로·혜화). 현재는 `A / B` 형태로 병기 |
| **명칭 출처가 위키백과(CC BY-SA 4.0)** | 연 1회 갱신 + `version` 필드로 노후화 표기. 소방서·경찰서는 연 1~2회만 개편됨 |
| **`2026-11` 스냅샷** | 2026 인천 행정개편(서해구·제물포구)·전남광주통합·강원특별자치도 반영분. 다음 개편 시 `agency-seed.json` + `sigungu.json` 교체 후 재생성 |

### 1.5 조회 동작 (폴백 포함)

```
주소 입력 → parseRegion()
            ↓
     loadRegionTable()   ← 1회 로드 후 메모리 캐시 (실패 시 5분간 재시도 안 함)
            ↓  성공                    ↓  실패(오프라인·파일 없음)
     lookupRegionRow()              규칙 기반 폴백
            ↓                          ↓
     applyRegionLookup(agencies, region, hint)
            ↓
     기관명은 note(입력칸)에, 라벨(name)은 일반 명칭 유지
     모든 값에 '확인' 체크 필요 (설계 원칙 유지)
```

**핵심:** 테이블이 없어도 게시판 기능은 100% 동작합니다. 이것이 2단계를 나중에 해도 되는 이유입니다.

## 2. 2단계 — Worker 프록시 + 지정병원 조회 ⬜

> 설계: `docs/emergency-live-lookup-design.md` §4 (Worker), §5 (스키마), §6.2 (UX)

### 2.1 착수 전 반드시 끝내야 하는 선행 작업

| # | 선행 작업 | 비고 |
|---|---|---|
| 1 | **공공데이터포털 활용신청** (국립중앙의료원_전국 응급의료기관 정보 조회) | 자동승인, 즉시 |
| 2 | **활용가이드(HWP)에서 오퍼레이션명·파라미터 확정** | ← **이게 안 되면 코드를 쓰면 안 됩니다.** 설계안은 `Q0`/`Q1` 을 잠정값으로 두고 있음 |
| 3 | Cloudflare 계정 보유 확인 | 없으면 사내 Node 서버 대안으로 전환 |
| 4 | 실제 응답 XML 1건을 `curl` 로 확보 | 파서를 추측으로 쓰지 않기 위해 **픽스처 먼저** |

### 2.2 작업 체크리스트

- [ ] Worker 작성 (`worker/` 신규) — 단일 파일, 의존성 0, 헬스체크 엔드포인트 포함
- [ ] `wrangler secret put DATA_GO_KR_KEY` — **키는 절대 프론트 번들에 넣지 않음**
- [ ] KV 네임스페이스 생성 + 24h 캐시 (설계 §4.5)
- [ ] XML → JSON 정규화 (실제 응답 픽스처 기준으로 작성)
- [ ] 레이트 리밋 (설계 §4.4)
- [ ] 프론트: `useHospitalLookup` 훅 + 후보 선택 UI
- [ ] 실패·타임아웃(3초)·오프라인 폴백 처리
- [ ] 조회 결과에 **출처 + 조회 시각** 표기
- [ ] 번들에 `serviceKey` / API 키 문자열 **0건** 확인

### 2.3 인수 기준 (설계 §12.3)

- [ ] 네트워크 차단 상태에서도 3·4번 항목을 끝까지 작성할 수 있다
- [ ] 온라인에서 지정병원 후보가 조회되고 선택 적용된다
- [ ] 조회 결과에 출처·시각이 표시된다
- [ ] 모든 자동 입력값에 '확인' 체크가 필요하다
- [ ] 프론트 번들에 API 키가 0개다
- [ ] **인쇄 결과가 A4 1페이지다** (현재 포스터 724px / 1047px — 여유 323px)
- [ ] 콘솔·페이지 오류 0건

### 2.4 예상 규모

6~8시간. 리스크 **중** (API 스펙 미확정, 응답 필드 변동 가능).

## 5. 검증 재실행 시 함정 (같은 실수 반복 방지)

1단계 브라우저 검증에서 **FAIL 3건이 전부 테스트 하네스 결함**이었습니다. 나중에 다시 검증할 때 아래를 지키면 불필요한 디버깅을 피할 수 있습니다.

| 함정 | 올바른 방법 |
|---|---|
| `textContent` 로는 `<input value>` 를 못 읽음 | 기관명은 `note`(input)에 있으므로 `locator.inputValue()` 사용 |
| 화면 폭(1400px)에서 잰 높이를 A4 기준과 비교 | `setViewportSize({width:718, height:1047})` + `emulateMedia({media:'print'})` 로 측정 |
| **`page.pdf()` 는 "현재 에뮬레이트된 미디어"로 렌더링** | PDF 생성 직전에 `emulateMedia({media:'screen'})` 로 되돌리면 앱 헤더·에디터까지 인쇄되어 **2페이지**가 됨. 인쇄 미디어를 **유지한 채** `page.pdf()` 호출 |
| `min-height:100vh` 가 인쇄를 넘치게 한다고 가정 | `EmergencyPlan.css` 인쇄 블록이 이미 `.app-main { min-height: 0 !important }` 처리함. `src/index.css` 에 보정 추가 불필요 (A/B 대조로 확인) |

**A4 기준값:** 인쇄 가능 높이 `1047px` = `(297-20)mm × 96/25.4`, 인쇄 레이아웃 폭 `718px` = `(210-20)mm`.

**임시 파일 주의:** 시드 페이지(`public/__*.html`)와 검증 스크립트(`*.mjs`)는 **커밋 전 반드시 삭제**. 현재 작업 트리는 깨끗합니다.
